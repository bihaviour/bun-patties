Server

Patties exposes two server entrypoints: createServer() for an in-process fetchable server handle, and startServer() for a real Bun.serve listener.

createServer

createServer is useful for tests or internal embedding. It compiles the route patterns and returns a fetch(req) function without binding a port.

startServer

startServer boots a real Bun server and forwards unmatched requests to the configured fallback handler.

Supported server options include:

  • port
  • hostname
  • unix
  • reusePort
  • routes
  • fallback
  • dev
  • devServer
  • staticRoutes

Embedding in another server

createRouter() returns { routes, fallback, entries }: a Bun.serve route table, a fallback handler, and the compiled route list. A host app can keep its own routes and mount Patties next to them:

const patties = await createRouter({ appDir: "./app", renderer: createRenderer({ manifest }) });

Bun.serve({
  routes: { ...hostRoutes, ...patties.routes },
  fetch: patties.fallback, // or your own 404
});

Collision and precedence rules — these come from Bun.serve's router and are covered by tests/integration/embedding.test.ts:

  • Different patterns: the more specific one wins, whichever table defines it — an exact path beats :param, which beats *. A host /users/me wins over a Patties /users/:id page, and a Patties /api/ping wins over a host /api/*.
  • Identical patterns: the table spread last replaces the whole entry, including every HTTP method. Method maps are not merged, so a host POST /about disappears when Patties also defines /about.
  • Patties registers only the files under app/routes/; check patties.entries (each has bunPattern) at boot if you need to assert there are no overlaps.
  • Unmatched requests go to whatever you pass as fetch.

Dev-only routes

When dev: true, Patties injects internal routes for:

  • __patties_open to open files in an editor
  • __patties_hmr for hot-module reload websocket traffic
